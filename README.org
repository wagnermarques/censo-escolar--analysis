Projeto Python para análise dos microdados do *Censo Escolar da Educação
Básica*, publicados anualmente pelo INEP.

Ele baixa os dados oficiais, organiza as ~370 colunas de cada edição e entrega
tabelas e gráficos prontos — sem que você precise lidar com ZIPs de centenas de
megabytes, codificação de arquivo ou os códigos numéricos do INEP.

#+begin_quote
*Como ler este documento.* A primeira metade é o *guia de uso*: instalar, baixar
os dados, rodar as análises. A segunda metade, a partir de
[[#por-dentro][Como o projeto funciona por dentro]], é a parte *técnica*: arquitetura
e decisões de implementação. Para usar o projeto, a primeira metade basta.
#+end_quote

* O que dá para fazer com isto

Com um ano de microdados baixado, você responde perguntas como:

- Quantas escolas, matrículas e docentes existem em cada estado?
- Qual a participação das redes municipal, estadual, federal e privada?
- Quantas escolas têm biblioteca, laboratório de informática, água potável,
  acessibilidade?
- Quais são os municípios com mais escolas?
- Como tudo isso mudou entre 2019, 2021 e 2023?

Cada uma dessas perguntas é uma linha de código, e todas devolvem uma tabela
que você pode ver na tela, virar gráfico ou exportar.

Você trabalha em *documentos de análise* — notebooks Jupyter com narrativa em
texto, intercalada com os comandos e seus resultados:

- =notebooks/00-preparacao-dos-dados-para-analise.ipynb= — que variáveis dá
  para comparar entre anos;
- =notebooks/01-panorama-escolas.ipynb= — análise descritiva de um ano.

  
* Instalação

Requisitos: Python ≥ 3.11. Nada além disso — sem gerenciador de pacotes externo. O
=make= é conveniência, não requisito — todo alvo é uma única chamada a
=python -m venv=, =pip= ou ao comando =censo= (instalado no =.venv= pelo
próprio =pip=), e a seção [[#windows][No Windows]] mostra o equivalente sem =make=.

** Criando o ambiente virtual

#+begin_src shell
make instalar     # python -m venv .venv + pip install -e ".[notebook,dev]"
#+end_src

Se preferir fazer à mão, ou não tiver =make=:

#+begin_src shell
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -e ".[notebook,dev]"
#+end_src

Depois de criado, ativar o venv (=source .venv/bin/activate= no Linux/macOS,
=.venv\Scripts\Activate.ps1= no PowerShell) deixa =censo=, =python= e =pip=
disponíveis sem prefixo de caminho pelo resto da sessão de terminal — é o
fluxo mais familiar para quem não mexe com Python no dia a dia. Os exemplos
deste documento usam o caminho completo (=.venv/bin/censo ...=) só para
funcionar igual com ou sem venv ativado.

=make= sozinho (ou =make ajuda=) lista todos os alvos disponíveis.

** No Windows
:PROPERTIES:
:CUSTOM_ID: windows
:END:

O pacote Python atravessa sem ajuste: =pathlib= em tudo, nenhuma chamada de

.venv\Scripts\censo lint              # make lint
.venv\Scripts\censo limpar            # make limpar

=.venv\Scripts\censo <alvo>= é o mesmo comando que o Makefile chama por baixo
(com =.venv/bin/censo <alvo>= em vez de =.venv\Scripts\censo <alvo>= em
Linux/macOS) — não é uma lista à parte para o Windows, é o jeito de rodar isto
tudo sem =make= em qualquer sistema. Quem usa WSL, MSYS2 ou Git Bash /com/
=make= instalado pode continuar com os alvos =make= normalmente: o Makefile
descobre sozinho se o venv guardou os executáveis em =bin/= ou em =Scripts/=.
Ele pergunta ao disco, não ao sistema operacional — é o que faz acertar até o
caso torto de um WSL enxergando um venv criado pelo Python do Windows, em que
a detecção por sistema operacional escolheria =bin/= e falharia.

*** Uma armadilha que não dá erro

*Caminhos longos.* Durante a extração, os anexos do ZIP do INEP chegam a ~180
caracteres de caminho relativo, e o Windows corta em 260 por padrão. Em
=C:\Users\voce\projetos\= sobra folga; dentro de um =C:\Users\voce\OneDrive -
Empresa\Documentos\...= o =censo obter= estoura no meio da extração. Clone perto
da raiz do disco, ou habilite o =LongPathsEnabled= no registro.


* Obtendo os dados

#+begin_src shell
make dados ANO=2023      # baixa o ZIP e extrai em data/interim/
make dados list          # o que já está no disco, ano a ano
make parquet ANO=2023    # converte o CSV de escolas para Parquet (leituras ~10x mais rápidas)
#+end_src

O =make dados list= é a resposta a "o que eu já baixei?" sem precisar de três
=ls=: ele junta os três estágios do pipeline — o ZIP em =data/raw/=, o extraído
em =data/interim/= e o Parquet em =data/processed/= — numa tabela por ano.

#+begin_src shell
ANO   ZIP        EXTRAÍDO  CSV DE ESCOLAS                             PARQUET
2023  30.6 MiB   sim       microdados_ed_basica_2023.csv (200.3 MiB)  40.0 MiB
2025  512.3 MiB  sim       Tabela_Escola_2025_V2.csv (134.9 MiB)      —

2 ano(s) baixado(s), 2 extraído(s), 1 em Parquet — 542.9 MiB em .../data/raw
#+end_src

Os estados do meio do caminho é que interessam: =parcial= na coluna do ZIP é um
download interrompido (o =.zip.part= que o =censo baixar= deixa), e =não
encontrado= na coluna do CSV é um diretório extraído pela metade — os dois casos
em que o ano *parece* estar no disco e não serve para análise.

Ou, com mais controle:

#+begin_src shell
.venv/bin/censo baixar 2023
.venv/bin/censo extrair 2023
.venv/bin/censo parquet 2023
.venv/bin/censo listar                      # inventário do que já está no disco
.venv/bin/censo colunas 2023 --filtro MAT   # lista as colunas do ano
.venv/bin/censo caminhos                    # mostra os diretórios resolvidos
#+end_src

** Se o download falhar
:PROPERTIES:
:CUSTOM_ID: download-falhou
:END:

O INEP muda o endereço dos microdados de tempos em tempos, e a URL embutida em
=src/censo_escolar/config.py= pode estar desatualizada. Duas saídas:

#+begin_src shell
# 1. informar a URL correta na hora
.venv/bin/censo baixar 2023 --url 'https://download.inep.gov.br/.../{ano}.zip'

# 2. ou fixar via variável de ambiente
export CENSO_ESCOLAR_URL='https://download.inep.gov.br/.../{ano}.zip'
#+end_src

Baixar o ZIP manualmente do site do INEP e colocá-lo em
=data/raw/microdados_censo_escolar_2023.zip= também funciona — o
=censo extrair 2023= segue daí.

*** =HTTP 404= num ano que existe

O INEP não é consistente no nome do arquivo. O pacote de 2025 foi publicado
como =microdados_censo_escolar_2025_.zip= — com um sublinhado sobrando antes da
extensão —, enquanto todos os outros anos seguem =..._{ano}.zip=. O resultado é
um 404 num ano que a página do INEP lista normalmente, o que engana: parece que
o ano não saiu.

Por isso =config.PADROES_URL= é uma *lista* de padrões, tentados em ordem até um
responder — mesma ideia do =_PADROES_ESCOLAS= em =loading.py=, que cobre as
variantes de nome do CSV. Se aparecer uma variante nova, acrescente-a lá e ela
passa a valer para todos os anos.

Antes de concluir que um ano não foi publicado, confira a
[[https://www.gov.br/inep/pt-br/acesso-a-informacao/dados-abertos/microdados/censo-escolar][página de microdados do INEP]]: testar o
padrão de URL que já temos não detecta um arquivo renomeado.

O ano de 2025 mudou mais coisas além do nome do arquivo — inclusive uma que
some com colunas sem avisar. Veja [[file:docs/microdados-2025.org][=docs/microdados-2025.org=]].

*** =ConnectionResetError= / =Connection aborted=

O servidor do INEP derruba a primeira conexão com alguma frequência, com um RST
no meio do handshake TLS. Não é erro de configuração sua: a tentativa seguinte
quase sempre passa — dá para confirmar com =curl -I= repetido no mesmo
endereço.

O =censo baixar= já sobe com retentativa e backoff (5 tentativas, cobrindo erro
de conexão, de leitura e 5xx), então esse tropeço é absorvido sozinho. Se ainda
assim estourar, é sinal de instabilidade maior do lado do INEP — espere e tente
de novo.

*** =unable to get local issuer certificate= / =SSLError=

O =download.inep.gov.br= envia apenas o certificado folha e *omite a CA
intermediária* (=RNP ICPEdu GR46 OV TLS CA 2025=) que o encadeia até a raiz
GlobalSign. Como nem o =certifi= nem o armazenamento do sistema trazem essa
intermediária, a verificação falha — o mesmo acontece com =curl= e com o
navegador em máquinas limpas.

O projeto resolve isso *sem desligar a verificação*: ao ver o erro de SSL, o
=censo baixar= baixa a intermediária a partir do campo "CA Issuers" do próprio
certificado do INEP, concatena com o bundle do =certifi= e repete o download.
Você verá a linha:

: Cadeia de certificados incompleta; baixando a CA intermediária…

Para montar o bundle antes da hora, ou refazê-lo depois de uma troca de
certificado:

#+begin_src shell
make certificados      # grava certs/inep-ca.pem
#+end_src

Se você já tem um bundle próprio (uma CA corporativa no meio do caminho, por
exemplo), aponte para ele e o projeto usa o seu:

#+begin_src shell
export CENSO_ESCOLAR_CA_BUNDLE=/caminho/para/meu-bundle.pem
#+end_src

#+begin_quote
*Não use =verify=False=.* É a "solução" que aparece primeiro em busca, e ela
desliga a verificação de todos os certificados para contornar a falta de um só.
O bundle acima resolve o problema real mantendo a checagem de pé.
#+end_quote


* Preparando os dados para análise

Cada edição do Censo tem um conjunto de variáveis um pouco diferente da
anterior: o INEP cria, renomeia e aposenta colunas todo ano, e em 2025 tirou
mais de cem delas do arquivo de escolas. Comparar anos sem saber disso produz
gráficos que despencam por causa do formato do arquivo, não da realidade.

Um comando responde o que dá para comparar:

#+begin_src shell
make dicionario          # ou: .venv/bin/censo dicionario
#+end_src

Ele varre todos os anos que você já baixou e grava
=data/processed/dicionario_colunas_comuns.csv=, com uma linha por variável
presente em *todos* eles: a descrição oficial do INEP, o domínio dos códigos
(=1 - Federal=, =2 - Estadual=…), o tipo que serve a todos os anos e um aviso
onde o tipo muda de um ano para o outro.

#+begin_src shell
.venv/bin/censo comuns                      # só a lista de colunas comuns
.venv/bin/censo comuns 2019 2020 2021 2022  # comuns a um recorte de anos
.venv/bin/censo dicionario --linhas 50000   # ensaio rápido (tipo não confiável)
.venv/bin/censo dicionario --todas          # inclui as não comuns, marcando quais são
#+end_src

O documento =notebooks/00-preparacao-dos-dados-para-analise.ipynb= faz o mesmo
caminho com a explicação de cada passo, e termina montando um painel de vários
anos só com as variáveis que o dicionário certificou. É o documento para rodar
primeiro — e
[[file:docs/tutorial-preparacao-dos-dados.org][=docs/tutorial-preparacao-dos-dados.org=]]
é o tutorial que o acompanha célula por célula.

#+begin_quote
*Por que o tipo vem dos dados, e não do nome da coluna.* O prefixo do INEP
sugere o tipo (=IN_= e =TP_= são inteiros pequenos, =QT_= conta, =CO_=
codifica), mas mente em alguns casos — e é sempre um caso silencioso. O CNPJ da
escola privada vem como texto em quase todos os anos e como número em um deles;
lido como número, perde o zero à esquerda e deixa de casar com o mesmo CNPJ dos
outros anos. Por isso o =censo dicionario= lê os arquivos inteiros como texto e
deixa os valores decidirem.
#+end_quote

* Usando no Jupyter — tutorial

Este é o caminho completo para desenvolver e rodar as análises: do zero até o
commit.

** Passo 1 — ambiente

#+begin_src shell
make instalar     # cria .venv e instala o pacote (editável) + jupyterlab + ipykernel
#+end_src

Um passo só: o extra =notebook= traz o =ipykernel=, que já registra um kernel
dentro do próprio venv, em =.venv/share/jupyter/kernels/python3/=. Confira:

#+begin_src shell
.venv/bin/jupyter kernelspec list
#+end_src

O =python3= dessa lista é o kernel do projeto — é ele que faz o notebook
enxergar o pacote =censo_escolar= instalado em modo editável.

#+begin_quote
*Por que não precisa registrar nada à mão?* O =kernel.json= que o =ipykernel=
instala diz apenas =python=, sem caminho. Quem resolve esse nome é o
=jupyter_client=, que o troca pelo =sys.executable= do processo que subiu o
servidor (=jupyter_client/manager.py=). Como =make lab= roda
=.venv/bin/python -m jupyter lab=, o kernel nasce no Python do venv — com
=censo_escolar=, pandas e pyarrow nas versões que os testes usam.

A pegadinha é usar um JupyterLab de *fora* do venv (do sistema, do pipx, ou de
outro projeto): esse não enxerga =.venv/share/jupyter/=, e aí o =import= falha.
A saída é rodar o Lab pelo venv — =make lab= — e não o Lab global.
#+end_quote

=Shift+Enter= executa a célula e avança; =Ctrl+Enter= executa sem sair do lugar;

#+end_src

** Passo 5 — o ciclo de desenvolvimento

Aqui está a parte que muda em relação a um notebook comum. *Nada de lógica nova
dentro de célula.* O ciclo é:

1. Você explora no notebook até a análise funcionar.
2. Assim que virar algo reutilizável (uma agregação, um recorte, um gráfico),
   move para =src/censo_escolar/= — =analysis.py= para agregações, =plots.py=
   para gráficos, =loading.py= para leitura.
3. Exporta o nome em =src/censo_escolar/__init__.py=.
4. Escreve o teste em =tests/=.
5. A célula do notebook fica com uma linha: a chamada.

Para não reiniciar o kernel a cada edição do pacote, ligue o autoreload na
primeira célula:

#+begin_src python
%load_ext autoreload
%autoreload 2
#+end_src

Com isso, salvar um =.py= em =src/censo_escolar/= já reflete na próxima
execução da célula. O autoreload não recupera tudo (mudança de assinatura de
classe, por exemplo) — quando o comportamento ficar estranho, =Kernel > Restart
Kernel and Run All Cells= resolve.

Rode os testes do lado de fora, sem fechar o Lab:

#+begin_src shell
make test
make lint
#+end_src

** Passo 6 — gráficos

No Jupyter, chame a função de plot *sem* o argumento =arquivo= e a figura
aparece inline:

#+begin_src python
plots.aplicar_estilo()                 # uma vez por sessão
plots.barras(uf.head(15), x="SG_UF", y="escolas", titulo="Escolas por UF")
#+end_src

Com =arquivo=, ela grava o PNG em =reports/figures/= e devolve o caminho como
string — útil para gerar relatórios/HTML sem interface. Se você mantiver o
=arquivo= no notebook, verá o caminho impresso em vez da imagem.

Para exibir *e* gravar, capture o eixo:

#+begin_src python
ax = plots.barras(uf.head(15), x="SG_UF", y="escolas")
ax.figure.savefig("../reports/figures/escolas_por_uf.png")
#+end_src

** Passo 7 — commitar

O JupyterLab roda com o diretório de trabalho em =notebooks/=, mas todo caminho
do pacote é resolvido a partir da raiz do projeto (=config.encontrar_raiz()=),
então =carregar_escolas= e =plots= acham os arquivos independentemente de onde
o kernel foi iniciado.

Salve o notebook no Lab (=Ctrl+S=) e commite normalmente:

#+begin_src shell
git add notebooks/ src/ && git commit -m "..."
#+end_src

Tudo que é lógica de análise fica em =src/censo_escolar/=: leitura dos CSVs,
dicionários de códigos, agregações, gráficos. São arquivos =.py= comuns,

Os documentos de análise ficam *magros*: importam do pacote, chamam funções,
mostram tabelas e gráficos, e escrevem a narrativa em volta. Se você se pegar
escrevendo uma função dentro de uma célula de notebook, ela pertence a
=src/censo_escolar/=.

** Por que os caminhos são resolvidos a partir da raiz

O Jupyter roda com o diretório de trabalho em =notebooks/=. Se o código usasse
caminhos relativos ao =cwd=, quebraria dependendo de onde o kernel foi
iniciado. Por isso =config.encontrar_raiz()= sobe a árvore de diretórios até
achar o =pyproject.toml=, e todo caminho sai de lá.

** Tipos e os códigos alfanuméricos do INEP

Os dtypes são escolhidos pelo prefixo da coluna (=IN_= e =TP_= viram =Int8=,
=QT_= vira =Int32=, =CO_= vira =Int64=, =NO_=/=SG_=/=DS_= viram =string=). É o
que segura o consumo de memória num arquivo de ~370 colunas.

Só que o prefixo mente em alguns casos: =CO_ORGAO_REGIONAL=, apesar do =CO_=,
traz valores como =0MI11= em parte dos estados. Quando a conversão falha, a
leitura *não quebra* — o CSV é relido em modo tolerante, cada coluna é
convertida individualmente e as que não forem numéricas de fato permanecem
texto, com um aviso dizendo quais foram:

: UserWarning: Colunas lidas como texto por conterem valores não numéricos: CO_ORGAO_REGIONAL

Repare que o fallback preserva o valor original em vez de aplicar um
=errors="coerce"=, que transformaria =0MI11= em nulo silenciosamente — e também
preserva os zeros à esquerda (=00009=), que um =Int64= comeria.
